Text Studio case study.

One Flutter app, fifteen text tools, and an ads system built so the free tier never gets in the way of the task.

The problem

Small text jobs come up all day: counting words before a submission, fixing the case of a pasted paragraph, stripping duplicate lines, making a QR code, translating a sentence, locking a note.

Each job usually sends people to a different single-purpose app, and the free ones tend to put an ad in the middle of the task. We set two rules for ourselves: simple jobs must work with no connection, and ads must pay for the app without making people leave.

The solution

Text Studio puts every tool one tap from a single home screen. Six core tools are free, work offline and open instantly with no ad gate. The other nine open after a short ad, and the app says so up front: a small video icon marks the tile, and when there is no internet those tools grey out with a clear label instead of failing after a tap.

Behind the screen sits a reusable ads module that owns consent, ad formats and reloads, so the app code stays about the tools, not about ads.

Designing the home screen

  • Pinned header. The branded header stays in place while the page scrolls, and its shadow deepens once you move, so it reads as a layer above the content.
  • Featured carousel. Four featured tools sit in large gradient cards at the top, so the highlights are one tap away without scrolling.
  • Colour-coded grid. Every tool has its own gradient and icon in a three-column grid. People learn a tool by colour before they read the label.
  • Honest offline state. Tools that need the network grey out and say “No internet” when the connection drops, instead of opening a screen that cannot work.
  • Visible ad marker. A small video icon on a tile means “short ad first”. Nothing about the free-tier deal is hidden.
  • Light and dark themes. One toggle in the header; every colour comes from a central palette, so both themes stay consistent.
  • Polite exit. On Android the back button asks before closing the app, so a stray swipe does not lose someone's place.

Ads that stay out of the way

Ads are the app’s only revenue, so we treated them as a product feature, not an afterthought. The module is built once and reused across PSBM apps.

  • One guarded entry point. A single navigator checks the connection, shows the right ad (rewarded, rewarded-interstitial or interstitial, depending on the tool) and only then opens the tool.
  • Consent first. A consent manager built on Google’s UMP flow handles GDPR choices, and a privacy policy screen is part of the app.
  • Tunable without a release. Ad flags are read from a small JSON file hosted on our own site, so ad behaviour can be adjusted without publishing a new build.
  • Recovers by itself. When the connection returns, listeners on the connectivity state and the module guard trigger ad reloads, so a tool does not stay locked after a temporary drop.

Engineering notes

  • One model drives the screen. A single tool model (title, icon, gradient, needs-network, ad-gated, on-tap) feeds both the carousel and the grid. Adding a tool is one entry and one route, and the offline and ad behaviour come with it.
  • Navigation from anywhere. Named routes with go_router, triggered through a small navigation service, so a tool can open from an ad callback without passing context around.
  • State and sizing. Provider carries connectivity state; flutter_screenutil keeps spacing and type consistent from small phones to large ones.
  • Local-first data. Hive stores saved data on the device, and text encryption uses AES-256, also on the device.
The same ads module now runs the PRO tiles in DailyShield, which is the point of building it as a module.

What we took from it

  • Say what is free and what needs an ad on the tile itself. It costs nothing and removes surprise.
  • Decide early which tools need the network. The grey-out state is then a one-line rule, not a bug list.
  • Keep a single source of truth for the tool list, so UI changes never drift from behaviour.

The result

Text Studio is live with fifteen tools and keeps growing: a new tool is one model entry plus one route, and it inherits the offline and ad behaviour automatically. The ads module built here now also powers the PRO tiles in DailyShield, so the work was reused instead of rebuilt.
