DailyShield case study.

Ten tools for everyday protection, tied together by one idea: a Shield Score that fills as you look after the basics each day.

The problem

Looking after yourself and your things is a lot of small, repeating jobs: save the receipt before it fades, change the password that is due, write down what you need to remember, drink water, take the medicine, pray on time, keep the phone quiet where it matters, and know who to call when something goes wrong.

People spread these jobs over many apps, and nothing tells them at the end of the day whether they actually covered the basics.

The solution

DailyShield brings these jobs into one app built around a single idea: the Shield Score. Five daily tasks fill a ring pinned to the top of the home screen, and it resets every midnight. Five more tools sit beside them and do not affect the score, so someone who only needs Emergency Contacts is never nagged about water.

Designing the Shield Score

  • Always visible. The score card is pinned above the scrolling module grid, so progress never scrolls away. A row of small icons shows each daily task and fills with that module’s colour when it is done.
  • Calculated, not hard-coded. The score is completed tasks divided by live daily tasks. Switch a module on or off and the percentage stays correct with no extra code.
  • A ring that moves. The ring is custom-painted with a gradient sweep and animates to its new value, so finishing a task feels like progress.
  • Plain-language labels. Not started, Warming up, Almost there, Fully shielded. People read a word faster than a number.
  • Explains itself. Tapping the card opens a sheet listing every daily task, what counts as done, and a Start button that opens that module directly.
  • Stays fresh. Progress reloads when the app resumes and when you come back from a module. Pull to refresh uses a branded indicator.

Designing the module grid

  • Gradient-bordered cards. Each module has its own colour pair, a gloss highlight and a tick badge when its daily task is done. A smooth colour wash replaced radial blobs that looked smudgy on some screens.
  • Calm entrance. Cards fade and rise in a short stagger, so the screen feels alive without slowing anyone down.
  • One module model. Every card comes from a single model (title, subtitle, icon, gradient, needs-network, live, daily-task, shows-ad, on-tap). The home screen only renders the list, so adding a module does not touch the layout.
  • Remote-ready availability. A single flags map decides which modules are live. It is the hook for switching a module on or off from a server later.

Local-first and offline-capable

Personal data stays on the device: receipts, password dates, notes and emergency settings are stored in local Hive boxes. Six of the ten modules open without any internet check, and the four that need a connection go through a shared module guard that responds clearly when offline instead of failing silently.

The Emergency Contacts hub is a good example: emergency numbers for more than 190 countries ship inside the app as a JSON asset, and the country is detected automatically, so the numbers are there even with no signal.

Ads, designed around Play policy

  • Banner kept apart. The adaptive banner sits in a fixed slot at the bottom, outside the scrolling content, separated by a gap and a hairline divider, so it never overlaps or hides tappable controls.
  • PRO means free, with an ad. Four tools open after a rewarded ad. A legend at the top of the grid says so: “PRO tools are free. Watch a short ad to open them.”
  • No dead taps. While an ad is still loading, the PRO tile is disabled and shows a short countdown label, so a tap never leads to nothing.
  • Reused module. The consent, guarded navigation and ad-readiness logic come from the same module that runs Text Studio.

Engineering notes

  • Receipt pipeline. Pick the photo, crop it, compress it, run ML Kit text recognition, pull out the merchant and amount, and save to local storage.
  • One daily tracker. A small service answers “which tasks are done today?” for all modules in a single call, so the score does not cause a read per card.
  • Fast start. Push-notification setup is deferred until after the first frame, so it never delays the home screen.
  • Stack. Flutter, Provider for connectivity state, go_router named routes, flutter_screenutil for consistent sizing, Hive for storage.

What we took from it

  • A single score gives a busy person one reason to open the app each day, without forcing them through every tool.
  • Derive numbers from live data. It removed a whole class of “score says 50% but shows 5 of 5” bugs.
  • Make the ad deal visible and the ad slot predictable. It is better for people and safer for store policy.

The result

The core loop is in place: ten modules, a score that stays accurate when modules are switched on or off, offline-capable tools, and an ad setup designed around Play Store policy. DailyShield is in active development, with new modules added through the same module model without touching the home screen layout.
